# P9-04 发布与回滚手册

> 2026-11-15。服务器不是 git 仓库，代码靠 tar 同步；发布/回滚以“代码包 + 数据库备份”为单位。

## 1. 发布包

当前发布快照：

```
/hy-tmp/campus/backup/release-v1.0.0-20261115.tar.gz   (1.2MB)
```

包含：`backend/`、`frontend/dist/`、`scripts/`、`migrations/`、`.env.example`。
不含：`.env`、`data/`、`venvs/`、模型权重（这些在 `/hy-tmp/campus` 与镜像/OSS）。

生成命令（每次发布前）：

```bash
cd /hy-tmp/campus/app
tar -czf /hy-tmp/campus/backup/release-v1.0.0-$(date +%Y%m%d).tar.gz \
  backend frontend/dist scripts migrations .env.example
```

## 2. 发布检查单

1. `pytest -q`（unit）与 `TEST_MYSQL=1 ...`（集成）全绿；
2. 前端 `npm ci && npm run build` 成功（`markdown-it`/`dompurify` 已在 package.json）；
3. `bash scripts/backup.sh` 或至少 DB/Chroma 快照；
4. 记录当前 `release` 包与 `git` 版本；
5. 同步代码 → `bash scripts/stop.sh backend && bash scripts/start.sh backend`；
6. `curl /readyz` 四项 ok + 冒烟（访客问答/登录/知识库列表）；
7. 公网首页 200、SSE 逐块。

## 3. 回滚步骤（目标 <10 分钟）

1. 保留现场：把当前 `backend/` 打 tar 备份；
2. 解压上一版发布包到临时目录，替换 `backend/` 与 `frontend/dist/`；
3. `bash scripts/stop.sh backend && bash scripts/start.sh backend`；
4. `curl /readyz` + 冒烟；
5. 若数据库迁移不可逆，先停服并用最近 DB 备份恢复（见 `docs/25`）。

实测：发布包解压 + 20 条回归测试约 **9 秒**；实际替换 + 重启预计 <1 分钟（不含 vLLM，vLLM 不受影响）。

git tag -a v1.0.0 -m "课程交付 v1.0.0"

## 5. 已知限制

- 服务器无 git，回滚靠 tar 包，不是 `git checkout`；
- 数据库迁移只做向前兼容，回滚代码不回滚库；
- `release` 包不含 `.env`，回滚不覆盖密钥配置。
