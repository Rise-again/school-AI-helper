- 测试：44 通过 / 5 跳过（跳过的是需要真库的集成用例）。新增 14 条切片/解析 + 5 条入库编排。

**踩到并修掉的坑**
- 切片会超出上限 1–2 token：估算函数带 +2 的边界开销，`hard_split` 没预留 → 改为按 `max-2` 分配，并在 emit 时二次校验。

**需要说明的一处取舍**
- PDF 默认按页抽取（pypdf），不是整篇 MarkItDown。原因：MarkItDown 转 PDF 会丢页码，而引用必须能指到"第几页"。MarkItDown 仍负责 docx/pptx/xlsx/html。若你要求严格只用 MarkItDown，把 `PARSE_PDF_MODE=markitdown` 即可切回（代价是没有页码）。

- 补 **token 预算裁剪**：历史按 token 从旧到新裁，历史占一半预算（1400 token），超长会话不会撑爆 4K。
- **分类与改写合并成一次 LLM 调用**（输出 JSON：intent + keywords），省一次模型往返。
- AnySearch 超时 12s→5s，符合"5 秒内降级"。
- vLLM 参数：`gpu-memory-utilization 0.75`、`max-num-seqs 16`（原 0.70/8，10 并发会排队）。

**实测**
- 路由准确率 **92%**（23/25，固化为 `scripts/evaluate_routing.py` + 25 条用例，可复现）。

**P3 查询改写升级：官方术语 + 知识库文件名提示（2026-11-14）**
- 现象：勤工助学 20 个口语问法里，多数检索不到证据，或匹配到无关片段；同一片段用口语长句打分 0.037，用规范化关键词打分 0.99（28 倍差距）。
- 结论：不是向量化或相似度算错，是**查询与语料用词不一致**——知识库是公文，用户说口语。
- 方案（不做同义词表）：路由节点一次调用同时产出意图与检索关键词；提示词要求"把口语换成公文说法 + 按语义扩写"（冲突→影响学习、能拿多少钱→劳动报酬）；把知识库文件名前 30 个作为"参考用词"注入提示词（60 秒 TTL 缓存）。关键词没命中时仍回退原句检索。
- 生成侧同步修：把"只写结尾参考行不算标注"写进规则，并把作答提醒放到资料之后 → 正文标注率 2/20 → 17/20；自行补岗位名/材料清单的情况大幅减少。提示词升到 p3-v2。
- 结果：20 题全部命中证据并作答，首字 0.95–1.14 秒；路由 96%（24/25）、RAG Recall@5 100%、单测 89 通过。详见 `docs/11-问答抽检报告.md`。

**P3 防幻觉门禁：证据可用性 + 回答落地校验（2026-11-14）**
- 背景：用户明确要求"所有回答必须有真实依据，没有就说不知道，不许捏造"。实测 7B 模型在资料没写时用常识补全：问"勤工俭学做些什么"答出"图书馆管理、行政助理"，问"要准备什么材料"答出"身份证复印件、家庭经济状况证明"，问"评优评奖有没有帮助"靠官网导航页片段答出"有助于提升综合素质"。
- 改动三处：
  1. **联网证据可用性门禁**（`nodes.py`）：正文 <80 字或通篇没有完整句子的网页不进证据集。导航页/栏目页的碎片重排分能到 0.95，但只会让回答变成正确的废话。
  2. **关键词弱则原句兜底**（`nodes.py`）：改写后知识库最高分 <0.50 视为改偏，用原句再检一次并合并结果。此前只判断"是否为空"，关键词返回一堆 0.1 分碎片时不兜底，正确片段反而被挤掉。
  3. **回答落地校验**（新增 `services/grounding.py`）：书名号标题、带单位的数字、"包括/如/例如"后的顿号列举，必须在证据原文里找得到；越界编号（资料 3 条却写 `[7]`）同样算违规。违规先让模型就地改一次（只改涉事分句，不许整段放弃），仍违规则删句，删成空壳降级为拒答。校验后通过 SSE 新增的 `replace` 事件整段替换前端已显示内容，落库只存修正版。
- 提示词同步：`p3-v3` 加固"只写参考行不算标注""不许用流程充数"，`p3-v4` 把修复提示改为"就地改、不许整段放弃"（此前一被判定违规就整段回"资料中没有直接说明"，把能答的问题也答废了）。
- 效果（20 题抽检）：全部有证据、无空答；拦截改写 4 条；捏造岗位名/材料/数字清零；首字 0.93–1.43s。回归：路由 96%、RAG Recall@5 100%、单测 117 通过。
- 踩坑：修复提示写"如果答不了就说资料中没有直接说明"时，模型会把整段有效回答换成拒答（Q8 命中文档 0.987 却答不出来）；改成"只改有问题的分句、其余原样保留"后恢复正常。另一坑：修复只返回 `[2]` 这种空壳，直接替换会把回答搞没；现在空壳会被判定并退回原始回答做删句兜底。
