# 架构设计（骨架，P1 起逐步填充）

## 1. 部署拓扑

```
                    ┌────────────── 云端 Ubuntu 20.04（单机）──────────────┐
浏览器 ──HTTPS──▶   │  uvicorn(1 worker) ─ FastAPI ─┬─ MySQL 8.0             │
                    │                               ├─ ChromaDB（本地持久化）│
                    │                               └─ httpx ──┐            │
                    │  vLLM :8001（独立 venv）◀────────────────┤            │
                    │  model-service :8002 ◀───────────────────┘            │
                    │      ├ bge-large-zh-v1.5                              │
                    │      ├ bge-reranker-v2-m3                             │
                    │      └ PaddleOCR                                      │
                    └───────────────────────────────────────────────────────┘
```

开发期把 MySQL / Chroma / FastAPI 放在 Windows 本机，模型仍指向云端，其余不变。
云端 Python 3.10 由 conda 提供（20.04 自带 3.8 不可用，见 D-07）。

## 2. 为什么必须单 worker

ChromaDB 以嵌入式方式写入本地目录，多进程会争抢集合锁；限流计数在进程内存里，多 worker 会让配额按进程各算一份。所以 `uvicorn --workers 1`，并发能力靠 async + vLLM 批处理，不靠多进程。

## 3. 分层与边界

| 层 | 目录 | 允许依赖 | 禁止 |
|---|---|---|---|
| 路由 | `api/v1` | schemas、services | 直接写 SQL、直接调 SDK |
| 业务 | `services` | repositories、integrations、agents、rag | 拼 HTTP 响应 |
| 数据 | `repositories` | domain | 业务判断 |
| 编排 | `agents` | rag、integrations（经接口） | 直接访问数据库 |
| 检索 | `rag` | integrations（embedding/rerank 客户端） | 直接读文件系统以外的外部服务 |
| 集成 | `integrations` | httpx、school-sdk | 业务逻辑 |

## 4. 两条主链路

**问答链路**：`POST /conversations/{id}/messages` → 鉴权与限流 → LangGraph 状态机 →（静态检索：embedding → Chroma 召回 20 → rerank 取 5）/（动态搜索：AnySearch → 域名过滤）/（教务：school-sdk）→ 组装提示词 → vLLM 流式生成 → SSE 推送 → 落库消息与引用。

**入库链路**：`POST /kb/files` → 校验 → MarkItDown 解析 → 空文本检测 →（是）调 `/v1/ocr` → 切片（≤480 token）→ 批量 `/v1/embeddings` → 写 Chroma + 元数据 → 更新解析状态。

## 5. 关键决策

| 编号 | 决策 | 理由 |
|---|---|---|
| A-01 | 所有模型在云端，本地零模型依赖 | 避免 Windows 装 torch/paddle；算力集中 |
| A-02 | 不引入 Redis / Nginx / ORM / 向量库以外的中间件 | 选型冻结；单机规模够用 |
| A-03 | LangGraph 不用持久化 checkpointer | 会话历史存 MySQL，避免额外依赖与状态双写 |
| A-04 | LoRA 不合并，vLLM 热挂载 | 量化基座合并会掉精度 |
| A-05 | TLS 由 uvicorn 终止 | 不引入反向代理 |
