> 2026-11-15，LoRA 版现网演练。环境：单机 RTX 4090 24GiB 容器，后端单 worker，vLLM 8001，model-service 8002，MySQL/Chroma 同机。
> 演练前备份：`/hy-tmp/campus/backup/db-pre-p7drill-20261115.sql.gz`（238KB）、`chroma-pre-p7drill-20261115.tar.gz`（2.1MB）。
> 前端验证：服务器上临时 Playwright + Chromium（`/tmp/pwvenv`、`/tmp/pw-browsers`），真实渲染页面、截图并收集 console error；截图在 `docs/p7-drill-shots/`。

## 1. 结论

六种规定场景 + 1 个附加场景全部通过：**均无可视白屏、均有可读提示、均有明确恢复路径**。演练中发现的 4 个降级缺口已当场修复并重新部署。

| # | 场景 | 注入方式 | 用户看到 | 恢复方式 | 结论 |
|---|---|---|---|---|---|
| 1 | vLLM 宕机 | `stop.sh vllm` | “抱歉，回答服务暂时不可用，请稍后再试”，无转圈/白屏 | `start.sh vllm`，36 秒就绪 | ✅ |
| 2 | ChromaDB 不可用 | 把 `data/chroma` 换成普通文件后重启后端 | “我没有在知识库里找到…依据”，知识库管理页正常 | 恢复目录 + 重启后端，33 秒 | ✅ |
| 3 | MySQL 断连 | `service mysql stop` | 访客页“服务暂时不可用，请稍后再试”；登录页“服务器内部错误，请稍后重试” | `service mysql start`，16 秒恢复，登录正常 | ✅ |
| 4 | AnySearch 超时 | `/etc/hosts` 指向黑洞 IP + 重启后端 | 无报错，正常用知识库作答（联网静默降级） | 恢复 hosts + 重启后端 | ✅ |

## 2. 逐项记录

### 2.1 vLLM 宕机（14:45:16–14:46:00）

- `stop.sh vllm` 后 `/readyz` 立即 503：`{"status":"degraded","components":{"llm":"down",...}}`。
- 访客页发“你好”：路由降级为关键词意图，检索仍可用；生成连接失败，返回 `MODEL_DOWN_REPLY`。页面文本长度 113，**无 cursor、无 console error**（截图 `ui-drill1-model-down.png`）。
- 日志：`llm_stream_failed: 模型流式调用失败：ConnectError`；`chat_metrics` 中 `model_down=true`、`first_delta_ms=null`。
- 恢复：`start.sh vllm` 36 秒到 `/readyz` 全绿。

### 2.2 ChromaDB 不可用（14:46:10–14:46:43）

- 停后端，把 `/hy-tmp/campus/data/chroma` 目录改名，并 `touch` 成普通文件，再启动后端；日志：`vector_store_unavailable: [Errno 17] File exists`。
- 访客页问“勤工助学的报酬标准是什么”：知识库检索跳过（`kb_unavailable`），联网也没有可用证据，返回 `NO_EVIDENCE_REPLY`；文本长度 138，无 console error（`ui-drill2-chroma-down.png`）。
- 管理员登录后知识库管理页正常渲染文件列表（数据来自 MySQL），无白屏（`ui-drill2-knowledge.png`）。
- 恢复：删除占位文件、还原目录、重启后端；再次提问 `meta → delta` 正常。

### 2.3 MySQL 断连（14:48:21–14:48:48）

- `service mysql stop` 后 `/readyz` 503，`mysql: OperationalError (2003)`。
- 访客页提问：检索需要查 `kb_file`，异常被流式接口兜住，页面显示“出错了：服务暂时不可用，请稍后再试”，无 console error（`ui-drill3-mysql-down.png`）。
- 登录页提交：返回 500，页面显示“服务器内部错误，请稍后重试”，无白屏；console 有 1 条 500 资源错误，属预期（`ui-drill3-login.png`）。
- 恢复：`service mysql start` 后 16 秒 `/readyz` 全绿，管理员登录/知识库页正常（`ui-drill3-restored.png`）。

### 2.4 AnySearch 超时

- 容器没有 `iptables` 权限，改用 `/etc/hosts` 把 `api.anysearch.com` 指向 `10.255.255.1`，重启后端确保新连接走黑洞。
- 问“学校最近有什么通知？”（含“最近”，强制联网）：AnySearch 5 秒超时，日志 `search_failed: 搜索服务不可用：ConnectTimeout`；知识库命中体质测试通知，正常作答，用户无感（`ui-drill4-search-timeout.png`）。
- 恢复：还原 `/etc/hosts`、重启后端，DNS 恢复为 `179.255.102.224`。

### 2.5 磁盘满

- `fallocate` 把 `/hy-tmp` 填到只剩 1MB（`df` 显示 100%）。
- 管理员登录后上传 3.1MB PDF：接口返回 **503 / code 6001 / “存储空间不足或文件写入失败，请联系管理员”**，日志 `upload_write_failed: OSError [Errno 28] No space left on device`。
- 写文件发生在 `create_file` 之前，因此**没有产生脏 DB 记录**。
- 恢复：`rm` 填充文件，`/hy-tmp` 立即回到 13G 可用。

### 2.6 显存 OOM

- 停 vLLM 后用 `GPU_MEM_UTIL=0.98` 启动：vLLM 日志明确报
  `ValueError: Free memory on device (19.85/23.53 GiB) ... less than desired GPU memory utilization (0.98, 23.06 GiB)`，
  EngineCore 初始化失败，进程退出；GPU 只剩 model-service 3.3GiB。
- `/readyz` 503 `llm: down`；访客页显示 `MODEL_DOWN_REPLY`，无白屏（`ui-drill6-oom.png`）。
- 恢复：`stop.sh vllm` 清掉残留 pid，再用默认 0.75 启动；恢复后 vLLM 18362MiB + model-service 3308MiB，`/readyz` 全绿。

### 2.7 附加：model-service 宕机

- `stop.sh models` 后 `/readyz` 503 `models: down`。
- 访客提问：embedding 连接失败 → `kb_unavailable`，联网拿到 1 条但被可用性门禁丢弃 → 正常拒答；页面文本长度 138，无 console error（`ui-drill7-models-down.png`）。
- 恢复：`start.sh models`，模型惰性加载，`/readyz` 全绿。

## 3. 演练中修复的缺口

| 问题 | 修复 |
|---|---|
| Chroma 初始化失败时 `/readyz` 仍全绿，监控会漏报 | `/readyz` 增加 `chroma` 组件（读 `vector_store.count()`），不可用时 503 |
| 向量库/embedding 不可用时 SSE 直接抛异常，用户只看到“服务异常” | 检索节点捕获 `DependencyUnavailable`，置 `degraded=kb_unavailable`，继续尝试联网或拒答 |
| 流式接口异常把 Python 异常类名暴露给用户 | 统一改为“服务暂时不可用，请稍后再试”，异常写日志 + trace_id |
| 磁盘满时上传只返回“服务器内部错误” | 写文件捕获 `OSError`，返回 503/6001“存储空间不足或文件写入失败，请联系管理员” |

修复后服务器实际部署代码全量测试 **162 通过 5 跳过**；演练结束 `/readyz` 全绿（`mysql/llm/models/chroma`），正常知识库问答恢复。

## 5. 已知限制

- 容器没有 systemd，上述 vLLM/model-service 崩溃**不会自动拉起**；D-19/D-27 已记录，P9-01 决定保持手动 `start.sh`。
- 磁盘满演练只验证了上传接口，没有在 UI 上实际拖拽文件；知识库页面本身在故障期间可正常渲染。
- Playwright 环境（`/tmp/pwvenv`、`/tmp/pw-browsers`）和浏览器依赖是为演练临时装的，不进入交付物；依赖包已装在系统里，P9 镜像如不需要可清理。
- 演练期间的 `ERROR` 日志均属预期注入（`vector_store_unavailable`、`upload_write_failed`），恢复后无新增错误。
