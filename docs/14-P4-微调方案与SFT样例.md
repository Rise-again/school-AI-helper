## 1. 微调到底要教什么

只教**行为与格式**，不教事实：

- 引用规范：每个事实句句末带 `[n]`，最后一行 `参考：[...]`；
- 拒答：证据不相关或只沾边时，直接说"资料中没有直接说明"，不推测；
- 用词：把口语换成文件里的官方说法（勤工俭学 → 勤工助学、贫困生 → 家庭经济困难学生）；
- 不补细节：资料没写的岗位名、材料、金额、日期一律不加；
- 角色语气：访客/学生/管理员三种口径；
- 冲突处理：同一事项多版本时采信生效日期较新的。

**不放进训练集的内容**：教务个人数据（走确定性模板）、真实用户会话、评测集原题、任何姓名学号手机号。

## 3. 正式数据怎么造（P4-01）

- 来源：9 份制度文件（学生手册 2025 版）的切片，**不用两份《资助政策问答》**（它们与评测集同源，容易泄漏）；
- 方式：按条款模板生成"问题 + 证据 + 标准回答"三元组，再人工抽检；同一条款生成 3–5 种口语问法；
- 规模：500–1000 条，角色占比学生 60% / 访客 25% / 管理员 15%，拒答样本 ≥10%；
- 隔离：与 60 条评测集做 3-gram Jaccard ≥0.6 或 embedding 余弦 ≥0.9 的去重，命中即丢弃（P4-02 验收硬条件）；
- 格式：Llama-Factory sharegpt，`system` + `conversations`，与预览文件一致。

## 4. 训练参数与依据

基座 **Qwen2.5-7B-Instruct**，方法 **QLoRA**，单卡 RTX 4090 24GB。

| 参数 | 取值 | 依据 |
|---|---|---|
| 量化 | 4bit NF4 + double quant | 7B 权重由约 15GB 降到约 4.5GB，24GB 卡才能同时放激活与优化器 |
| 计算精度 | bf16 | 4090 原生支持 bf16，比 fp16 更不容易溢出 |
| LoRA rank / alpha | 16 / 32 | 任务只改格式与语气，不需要大容量；alpha=2r 是常用比例 |
| LoRA dropout | 0.05 | 数据量小，轻微正则防过拟合 |
| 作用模块 | 全部线性层（q,k,v,o,gate,up,down） | QLoRA 原论文做法，容量与显存平衡 |
| 序列长度 | 3072（紧张时回落 2048） | 系统提示词+证据平均约 1800 token，回答 ≤500；2048 会截掉约三成样本 |
| batch / 梯度累积 | 1 × 8 = 有效 8 | 单条 3072 已占显存；累积 8 等价 batch 8，稳定且省显存 |
| 学习率 | 1e-4，cosine，warmup 10% | QLoRA 7B 常用区间；小数据配 cosine 收敛平稳 |
| epoch | 3，早停 patience=3 | 500–1000 条数据 2–3 轮足够；监控 eval loss 防过拟合 |
| 优化器 | paged_adamw_8bit | 8bit 分页优化器，避免优化器状态把显存吃满 |
| 梯度裁剪 | max_grad_norm 0.3 | QLoRA 论文推荐值，抑制 spike |
| 梯度检查点 | 开 | 用时间换显存，激活从十几 GB 降到 6–9GB |
| packing | 关 | 避免不同样本串在一起，污染引用格式 |
| 评估切分 | 留出 10%，每 20 步评估 | 小数据也能看出过拟合 |
| 保存 | 每 50 步，留最近 3 个 | 可回退到中间 checkpoint |
| 随机种子 | 42 | 可复现 |
| 对话模板 | qwen（ChatML） | 与 vLLM 部署一致 |
| vLLM 挂载 | `--enable-lora --max-lora-rank 16` | 不合并权重，基座与 adapter 并存，3 分钟内可回退 |

显存估算（训练时）：4bit 权重 4.5GB + LoRA/优化器 <1GB + 激活 6–9GB + 上下文与缓冲约 2GB ≈ **14–16GB**。因此训练前必须停 vLLM（约 18GB）和 model-service（约 3GB），训练结束后再拉起；训练期间问答与 OCR 不可用，这正是你选择的停服窗口。

时间估算：800 条 × 3 轮 ÷ 有效 batch 8 ≈ 300 步，按 20–30 秒/步约 **1.7–2.5 小时**，加评估与存盘 3–4 小时，与计划"挂机 4–8 小时"一致。

## 5. 训练过程监控与报告协议

我会把训练日志、loss 曲线、eval loss、学习率、grad_norm 记录到 TensorBoard；按下面节奏向你汇报：

- **开工前**：确认基座、数据版本、参数、预期显存与时长；
- **25% / 50% / 75%**：发 loss 曲线截图 + 当前判读（是否健康、有无异常）；
- **50% 时**：用中间 checkpoint 生成 5 个固定问题（1 个引用题、1 个拒答题、1 个术语题、1 个多轮、1 个寒暄），和基座并排给你看，直观判断"学到没有"；这一步需要暂停训练约 3 分钟；
- **异常即时报告**：不等节点，立刻说明现象、可能原因、打算怎么处理；
- **结束**：最终 loss/eval、与基座对比、是否建议上线。

loss 现象判读表（也会写进训练记录）：

| 现象 | 本质 | 处理 |
|---|---|---|
| 初始 1.5–2.5，100 步内降到 1.0 以下 | 正常：模型在学格式 | 继续 |
| 长期平台在 1.2 以上 | 学习率偏小或数据太单一 | 提高 lr 或补充问法多样性 |
| 突然尖峰 >2 倍近期均值 | 遇到异常样本或 lr 过大 | 检查该步数据、必要时跳过 |
| NaN / inf | bf16 下少见，多为数据含异常字符或梯度爆炸 | 降 lr、加大裁剪、清洗数据 |
| eval loss 连续 3 次上升 | 过拟合 | 早停，取更早 checkpoint |
| grad_norm 持续 >10 | 训练不稳定 | 降 lr、检查长样本 |
| 回答长度明显变长 | 学到"啰嗦" | 检查是否混入长答案样本 |

## 6. 验收指标（微调 vs 基座，同一 60 条评测集、同一提示词、同一证据）

| # | 指标 | 定义与测法 | 门槛 |
|---|---|---|---|
| 1 | **编造率** | 回答中的具体名称/数字/列举在证据里找不到的比例；落地校验自动统计 + 人工复核 40 条 | 不高于基座，目标 <5% |
| 2 | **库外拒答率** | 真正库外的问题中给出"没有依据"式回答的比例（N07–N14 实际在库内，已从分母剔除） | 不低于基座；目标 ≥85%（P8-04 终值） |
| 3 | **正文标注率** | 事实句带 `[n]` 的比例 | 不低于基座（基座约 85%） |
| 4 | **引用正确率** | 抽 40 条回答，`[n]` 所指证据确实支持该句 | ≥90%，且不低于基座 |
| 5 | **过度拒答率** | 40 条可答题被错误拒答的比例 | ≤5%，且不高于基座 |
| 6 | 路由准确率 | 25 条路由用例（同一模型负责路由，需防退化） | ≥90%，不低于基座 3 个百分点 |
| 7 | 格式合规率 | 结尾"参考："行存在、编号不越界 | ≥95% |
| 8 | 长度合规 | 回答 ≤300 字 | ≥90% |
| 9 | 延迟 | 单用户首字与总时长 | 首字 ≤3s，不劣于基座 20% |
| 10 | 角色语气 | 三角色盲评偏好 | 参考项，不作门槛 |

**上线判定**：1–5 全部"不劣于基座"，且第 3 或第 4 项至少一项提升 ≥5 个百分点，才允许灰度上线；任何一项明显变差（>5 个百分点）直接否决。若路由退化，路由请求固定走基座、生成走 adapter。不达标就不上线，保留基座——这是已有 R1 预案。
