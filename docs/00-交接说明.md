## 4. 已经形成的几个关键设计（别推翻）

1. **级联检索**：永远先跑静态 RAG；top1 ≥0.80 且用户没要"最新"就只用知识库，否则补 AnySearch；两路证据统一重排，阈值 0.20，最多留 3 条。路由判错最多多查一次网，不会答错。
2. **查询改写用官方术语，不写同义词表**：路由一次 LLM 调用同时产出意图与关键词，提示词要求把口语换成公文说法（勤工俭学→勤工助学、能拿多少钱→劳动报酬），并把知识库文件名前 30 个作为"参考用词"注入（60 秒 TTL）。关键词检索最高分 <0.50 视为改偏，自动用原句再检一次并合并。
3. **联网证据门禁**：正文 <80 字或没有完整句子的网页（导航页、目录页）不进证据集——它们的重排分能到 0.95，但只会把回答引向"正确的废话"。
4. **回答落地校验**（`backend/app/services/grounding.py`）：书名号标题、带单位数字、"包括/如/例如"后的顿号列举，必须在证据原文里找得到（页眉打断的允许二元组 80% 匹配）；越界编号算违规。违规先让模型就地改一次（只改分句，不许整段放弃），仍违规则删句，删空降级拒答。修正结果走 SSE `replace` 事件整段替换，落库只存修正版。
5. **SSE 事件**：`meta → delta* → [replace] → citation → done`，每 2.5 秒 `: ping`（平台代理空闲 4 秒断流）。断线时用 `asyncio.shield` 保证已生成内容落库。
6. **配额三层**：24h 查询缓存 → 每用户每日 60 次 → 全局每日 1800 次；个人超限不消耗全局。

## 7. 已知坑（踩过，别再踩）

- 登录失败与令牌过期都是 `401 + code 2001`，前端必须特判 `/auth/login`，否则密码错会提示"登录已过期"。
- 同一片段用口语长句打分 0.037、用规范化关键词 0.990，**检索效果差先怀疑用词不一致，不要先怀疑向量化**。
- 检索结果**不要拿原句二次重排**：会二次降分把正确证据筛掉；KB 沿用关键词得分，只给联网结果补分。
- AI 补全幻觉集中在"资料没写但用户问细节"的场景（岗位名、材料清单）；仅靠提示词压不住，必须有落地校验。
- MySQL 需 `cryptography`（caching_sha2）；`mysqldump` 要 `-h127.0.0.1 --no-tablespaces`，否则静默导出 20 字节空文件。
- `oss` CLI：没有 bucket 名（`oss://` 就是根），不接受 `.tgz`/`.txt`，`oss rm` 要 `-f`。
- 前端构建要在虚机本地盘（`/tmp/fe`）做，Windows 共享目录装 npm 极慢；Vite 8 的 `manualChunks` 只接受函数。
- `pkill -f "npm install"` 会杀掉自己的 SSH 会话，用 `np[m]` 这种写法。
- PDF 页眉会把表格名切成两半（"海南热带海洋 -167- 海南热带海洋学院 …申请表"）。
