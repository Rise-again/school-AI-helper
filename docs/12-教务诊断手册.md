# 教务系统诊断手册（P5）

> 2026-11-14 首次整理。记录这次接教务踩到的所有坑与判定方法，下次教务再"抽风"按本文顺序排查，
> 不要重头猜。脚本都在 `scripts/` 下，只读、不提交任何数据。

## 1. 三个诊断脚本

| 脚本 | 在哪跑 | 作用 | 何时用 |
|---|---|---|---|
| `scripts/edu_probe_raw.py` | 能打开教务的电脑 | 只发 3 个 GET：登录页、RSA 公钥、首页，打印状态码/内容类型/正文开头/csrf 是否存在 | 判断"网络通不通、页面版本变没变"，不涉及账号密码 |
| `scripts/edu_probe.py` | 能打开教务的电脑 | 用 school-sdk 真登录，依次输出个人信息、课表、成绩的结构摘要；`--dump` 打印完整字段；`--debug` 打印请求日志并在卡住 45 秒后 dump 调用栈 | 验证账号、SDK 与字段结构 |
| `scripts/edu_e2e_local.py` | 能打开教务的电脑 | 用后端真实的适配层 + 映射函数跑"登录→课表→成绩→学分"，结果写 JSON | 服务器连不上教务时，用真实数据核对映射 |

共同前提：装的 SDK 必须是 `vendor/school_sdk-1.9.0.post1-py3-none-any.whl`（见第 4 节），密码交互输入、不回显、不落盘。

## 2. 排查顺序（从外到内）

### 第 1 步：网络可达性

在**目标机器**上跑：

```bash
# 教务本体
curl -sS -m 10 -o /dev/null -w '%{http_code} %{time_total}s\n' http://zfjw.hntou.edu.cn/jwglxt/xtgl/login_slogin.html
# 同校其他站点做对照
curl -sS -m 10 -o /dev/null -w '%{http_code}\n' http://www.hntou.edu.cn/
curl -sS -m 10 -o /dev/null -w '%{http_code}\n' http://jwc.hntou.edu.cn/
```

| 现象 | 判据 | 结论 |
|---|---|---|
| 教务超时/ping 不通，但 www/jwc/招生网正常 | 同校站点可达、唯独教务不可达 | **教务按来源 IP 放行**（2026-11-14 起只对校园网），非本系统故障 |
| 两边全超时 | DNS 或出口问题 | 先查 DNS、代理、校园网认证 |
| 教务返回 502（约 5 秒） | 能建连、网关回 502 | 境外/非白名单出口被网关拒绝 |
| curl 通、Python 超时 | 同一台机器两种客户端结果不同 | 查系统代理（`ProxyEnable`）、UA、WAF 拖拽；换 `curl.exe` 复测 |

### 第 2 步：登录页版本与路径

`edu_probe_raw.py` 的第 1、2 段：

- 登录页 200、含 `csrftoken`、`Set-Cookie: JSESSIONID` → 页面正常；
- 公钥接口 `application/json` 且含 `modulus/exponent` → 接口路径正确；
- 若公钥接口返回 `text/html` → **路径前缀不对**（见第 3 节 `/jwglxt`）。

### 第 3 步：SDK 登录

`edu_probe.py` 登录成功会打印 `登录成功`，随后 `check_session()` 返回 True。失败时按异常对号：

| 异常 | 常见原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: torch` | 用了 PyPI 的 `school-sdk 1.8.1`（顶层 import 验证码模块，强依赖 torch/torchvision） | 换 `vendor/` 里的 1.9.0.post1 wheel |
| `ImportError: cannot import name 'Bytes' from 'ast'` | SDK 源码残留 `from ast import Bytes`，Python ≥3.9 必崩 | 同上（补丁 wheel 已删该行） |
| `JSONDecodeError: Expecting value: line 1 column 1` | 端点缺 `/jwglxt`，公钥请求返回登录页 HTML | 配 `EDU_BASE_PATH=/jwglxt`（代码默认已带） |
| `LoginException(400, ...)` | 账号密码错、账号被锁 | 换正确密码；确认账号未被风控 |
| 登录后接口报"session 已失效" | 会话过期（正方返回 200 但内容是登录页） | 服务层会自动重登一次；二次仍失败再看网络 |

### 第 4 步：数据字段

`edu_probe.py --dump` 看课表首条与成绩前三条。2026-11-14 实测结构：

- 课表：`course / place / campus / teacher / weeks_text / week_day("1") / section("1-2") / weeks_arr / time`
- 成绩：`course_name / course_code / course_nature / exam_result("72"/"不合格") / exam_score / credit("4") / grade_point("2.20" 或 null)`
- 学年参数：`year` 传**学年起始年**（2026 表示 2026-2027），`term` 1/2；SDK 内部映射成正方的 `xqm`（3/12）。

### 第 5 步：服务端表现

服务器连不上教务时（典型：来源 IP 被限制）：

- `/api/v1/edu/status` 正常（只读数据库，不访问教务）；
- `/edu/schedule|grades|credits` 返回 **503 + code 6001**，message "教务系统暂时无法访问"；
- 对话里问课表/成绩 → 回复同样的降级话术；
- 日志 `campus.edu` 有 `edu_upstream_error`（含异常类名与截断信息，不含口令）。

## 3. 两个固定坑（已修，别再踩）

1. **路径前缀**：学校教务挂在 `http://zfjw.hntou.edu.cn/jwglxt/`，而 school-sdk 内置端点没有 `/jwglxt`。直接调用会把登录页 HTML 当 JSON。代码通过 `EDU_BASE_PATH`（默认 `/jwglxt`）给 SDK 的全部端点补前缀。
2. **Python 版本**：SDK 元数据写 `>=3.8,<3.14`，本机 3.14 装不上；补丁 wheel 是纯 Python，绕过版本限制可用，但项目生产环境是 3.11，按 3.11 为准。

## 5. 2026-11-14 事件记录

| 时间 | 现象 | 定位 | 处置 |
|---|---|---|---|
| 上午 | 云服务器访问教务超时，同校 www/jwc 正常 | ping 不通、80/443/8080/8443 全超时 → 来源 IP 被限制 | 记录为外部限制，D-09：按用户网络直连，不做隧道 |
| 下午 | 本机（校园网）SDK 报 `JSONDecodeError` | 公钥接口返回登录页 → SDK 缺 `/jwglxt` 前缀 | 探测脚本加 `--base-path`，后端加 `EDU_BASE_PATH` |
| 下午 | 校园网首次运行时 `requests` 读超时 | WAF 瞬时拖拽（`SS: s` 头）；curl 复测正常 | 重跑即成功，非代码问题 |
| 下午 | 登录成功，课表/成绩字段拿到 | 真实结构见第 2 节第 4 步 | 据此实现映射并固化单测 |

## 6. 快速结论表

- 能不能连教务 → 第 1 步的 curl；
- 是不是页面/路径变了 → `edu_probe_raw.py`；
- 是不是账号/SDK 问题 → `edu_probe.py`；
- 映射对不对 → `edu_e2e_local.py` 的输出；
- 服务端为什么 503 → 服务器上重复第 1 步，再查 `campus.edu` 日志。
