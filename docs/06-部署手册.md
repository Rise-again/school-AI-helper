# 部署手册（框架，P9 落地为可执行步骤）

## 1. 环境

| 环境 | 位置 | 用途 | 备注 |
|---|---|---|---|
| dev | Windows 11 本机 | 日常开发 | 不跑模型，模型全部指向云端 |
| staging | 无独立环境 | — | 单人项目，用 dev + 生产验证替代 |
| prod | 恒源云 Ubuntu 20.04 单机 | 对外服务 | RTX 4090 24GB（并发上限 10），含 vLLM 与 model-service；对外经平台自定义服务（8080） |

## 2. 端口

| 端口 | 服务 | 对外 |
|---|---|---|
| 443 | uvicorn（TLS 在此终止）+ 前端静态资源 | 是 |
| 22 | SSH | 仅限本人 IP |
| 8000 | uvicorn 明文（仅本机调试） | 否 |
| 8001 | vLLM | 否（仅 127.0.0.1） |
| 8002 | model-service | 否（仅 127.0.0.1） |

## 3. 目录

```
/opt/campus/
  app/           后端代码
  venv/          后端依赖
  web/           前端构建产物
  data/chroma/   向量库
  data/uploads/  上传文件
  logs/          日志（按天轮转）
  model-service/ 模型服务（独立 venv）
```

## 4. 进程托管

三个 systemd 单元：`campus-uvicorn.service`、`campus-vllm.service`、`campus-models.service`。均设 `Restart=always`、`RestartSec=5`；vLLM 冷启动慢，健康检查用 `ExecStartPost` 轮询 `/v1/models`，最多等 180 秒。

## 5. 部署步骤（P9-01 填充为脚本）

1. 建服务用户 `campus`，禁用其登录 shell
2. 安装系统依赖（python3.10-venv、build-essential、poppler-utils 等）
3. 建 venv，装 `backend/requirements-linux.txt`
4. 上传代码与前端产物，设置目录属主
5. 写 `.env`（密钥从本地安全通道传入，不写进仓库）
6. 启三个 systemd 单元，验证 `/healthz`、`/readyz`
7. 配置 uvicorn TLS 证书，openssl 校验证书链

## 6. 发布与回滚

发布：`git tag vX.Y.Z` → 拉取 → 装依赖 → 迁移脚本（向前兼容）→ 重启 → 冒烟（3 条主路径）。
回滚：切换 tag → 若迁移不可逆，用备份恢复数据 → 重启 → 冒烟。目标：10 分钟内完成。

## 7. 备份

MySQL 每日 `mysqldump` 保留 7 天；Chroma 目录每日快照；模型与 adapter 不进备份（可重新下载）。恢复演练在 P9-03 必须实做一次并记录耗时。

## 8. 巡检（P9-06）

每日看四项：磁盘水位（<80%）、显存占用、`/readyz` 三项依赖、AnySearch 当日配额余量。超阈值在日志里出 WARN 行。

## 9. 恒源云落地细则（2026-11-07 核实官方文档）

| 项 | 事实 | 对部署的硬性影响 |
|---|---|---|
| 对外端口 | 自定义服务**固定 8080**，必须监听 `0.0.0.0` | `uvicorn --host 0.0.0.0 --port 8080`；写 `127.0.0.1` 或换端口都转发不生效 |
| 系统镜像 | **Ubuntu 22.04.5 LTS**（2026-11-08 实测） | 与选型一致；系统 Python 3.11.12；**缺 ensurepip，`python3 -m venv` 会失败，必须用 virtualenv** |
| 系统盘 | 约 20GB | 只放代码与配置；conda 环境 / 模型 / 数据一律放 `/hy-tmp` |
| 数据盘 | `/hy-tmp`，**关机超 24 小时自动清空**，迁移实例也清空 | 不能当持久存储，必须每日备份到"个人数据"OSS |
| 个人数据 | OSS 云盘，跨实例、长期保存，**只能传压缩包** | 备份/恢复都走"打包 → `oss cp`" |
| 目录权限 | `/hy-tmp` 为同机多租户共享 | `chmod 700`，避免其他实例读到数据 |
| 实例回收 | 按量关机超 10 天实例删除 | 交付期保持开机或续费 |
| 公网链接 | 实测 `http://i-2.gpushare.com:44368/` → 内网 8080，**HTTP 无 TLS** | 答辩直接发这个链接；不买域名、不配证书；但令牌在公网明文传输，验收文档需注明 |
| 备份镜像 | 支持（实例管理 → 创建备份镜像），**只固化系统盘环境，不含 `/hy-tmp`** | 依赖装好后创建一次镜像，重装从 40 分钟降到 5 分钟；数据仍靠 OSS |
| 欠费 | 欠费满 15 天删除个人数据、共享存储、自定义镜像 | 保持余额充足 |

### 9.1 目录布局

```
/hy-tmp/campus/
  venv-web/          后端依赖（backend/requirements-linux.txt）
  venv-models/       bge + 重排 + PaddleOCR
  venv-vllm/         vllm（独立，torch 版本不共用）
  models/qwen2.5-7b-instruct/
  data/mysql/        MySQL datadir
  data/chroma/
  data/uploads/
  backup/            每日打包，随后 oss cp
/root/campus/        代码（系统盘，体积小）
```

### 9.2 备份与恢复

`/hy-tmp` **关机 24 小时即清空、迁移实例也会清空**，必须备份到「个人数据」云盘（同价 0.0004 元/GB/小时，31G 约 9 元/月）。

```bash
oss login                       # 首次，交互式输账号（只需一次）

bash scripts/backup.sh --full   # 首次 / 环境变更后：venv+代码+数据+自训产物
bash scripts/backup.sh          # 日常：数据库+上传文件+.env（几 MB）
bash scripts/backup.sh --full --with-models  # 连公开基座模型一起传（18G，一般不必）
bash scripts/backup.sh --prune  # 清理远端旧备份，保留最近 5 份

bash scripts/restore.sh --timestamp 2026-11-08-1200 --full
```

设计取舍：**公开基座模型不备份**（Qwen2.5-7B 与两个 bge 可从 ModelScope 重下，约 7 分钟，比传 18G 还快），但 `models/adapters`、`data/sft`、`data/training` 下的**微调产物永远备份**——这些网上没有，丢了就真没了。虚拟环境有几万个小文件，必须打包成 `.tar.gz`（注意：恒源云 oss **只收压缩包，且不认 `.tgz` 扩展名**）；公开模型只有 `--with-models` 时才打包上传。恢复脚本先把旧目录改名、失败自动回滚，不会留下半套环境。

**不需要每天跑 `--full`**：模型和 venv 稳定，只在环境有变更（装新包、换模型）时重传。

### 9.3 开机自检（P9-01 脚本化）

1. `df -h /hy-tmp`：不存在或为空 → 触发从 OSS 恢复
2. 检查三个 venv 与模型目录是否齐全，缺了按 `scripts/reinstall.sh` 重装
3. `ss -anplt | grep 8080`：确认端口监听在 `0.0.0.0`
4. 起 `mysqld` → `uvicorn --host 0.0.0.0 --port 8080 --proxy-headers --forwarded-allow-ips=*`
5. 起 vLLM 与 model-service，轮询 `/healthz` 直到就绪（最长 180 秒）
6. `curl -s https://<自定义服务地址>/healthz` 做端到端确认

### 9.4 一键安装（推荐）

```bash
git clone <仓库地址> && cd school_AI_helper
bash install.sh          # 全量：环境 + 依赖 + 模型 + 数据库
bash scripts/start.sh    # 启动三个服务
```

`install.sh` 幂等：重复执行只补缺失部分，不覆盖已有 `.env`。分步排障时才需要看下面的手动命令。

### 9.5 手动等价步骤（排障用）

镜像已带 PyTorch 2.9.1 + CUDA 12.8 + Python 3.11。**注意：install.sh 会在 models 环境里显式装 torch 2.9.1，保证换机器可复现；手动装时若复用系统 torch，需加 `--system-site-packages`。**

```bash
# web 环境：不需要 torch，独立 venv 即可
python3 -m virtualenv /hy-tmp/campus/venvs/web
/hy-tmp/campus/venvs/web/bin/pip install -r backend/requirements-linux.txt

# models 环境：复用系统 torch，省 2.5GB 下载
python3 -m virtualenv --system-site-packages /hy-tmp/campus/venvs/models
/hy-tmp/campus/venvs/models/bin/pip install FlagEmbedding paddlepaddle-gpu paddleocr

# vllm 环境：隔离安装，让它自带匹配的 torch
python3 -m virtualenv /hy-tmp/campus/venvs/vllm
/hy-tmp/campus/venvs/vllm/bin/pip install vllm==0.31.0

# 校验
/hy-tmp/campus/venvs/*/bin/python -V   # 都应是 3.11.x
```

> 实测踩坑：镜像里 `python3 -m venv` 报 `ensurepip returned non-zero exit status 1`（缺 ensurepip）。先 `pip3 install virtualenv`，再用 `python3 -m virtualenv` 建环境。若目录是先前失败的 venv 残留（只有 python 没有 pip），先 `rm -rf` 再建。
```

PaddlePaddle 若没有 cp311 wheel（装的时候看报错），单独用 conda 建 3.10 环境只跑 OCR：

```bash
wget -q https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O /hy-tmp/mini.sh
bash /hy-tmp/mini.sh -b -p /hy-tmp/miniconda3
/hy-tmp/miniconda3/bin/conda create -y -n ocr python=3.10
/hy-tmp/miniconda3/envs/ocr/bin/pip install paddlepaddle-gpu paddleocr
```

装完依赖立刻**创建备份镜像**，否则 `/hy-tmp` 一清空就要重来一遍。
