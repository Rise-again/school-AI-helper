# 数据库设计（表清单，P1 出完整 DDL）

## 1. 约定

统一 `utf8mb4` / `utf8mb4_0900_ai_ci`；主键 `BIGINT UNSIGNED AUTO_INCREMENT`；每表带 `created_at`、`updated_at`；软删除用 `deleted_at`（会话与文件）；枚举用 `VARCHAR` + 注释，不用 MySQL ENUM（改值要 DDL）。

## 2. 表清单（13 张）

| 表 | 作用 | 关键字段 | 关键约束 |
|---|---|---|---|
| `user_account` | 账号 | role(guest/student/admin)、username、password_hash、status、fail_count、locked_until | username 唯一 |
| `student_profile` | 学号绑定 | user_id、student_no、name、college、major、edu_cred_cipher | student_no 唯一；edu 凭据加密列 |
| `conversation` | 会话 | user_id、title、role_mode、deleted_at | 索引 (user_id, updated_at) |
| `message` | 消息 | conversation_id、role(user/assistant)、content、tokens、latency_ms、trace_id | 索引 (conversation_id, id) |
| `citation` | 引用 | message_id、kb_file_id、chunk_id、page_no、url、snippet、score | 外键 message_id |
| `kb_file` | 知识库文件 | filename、file_hash、file_type、**parse_channel（markitdown / pdf-text / pdf-text+ocr / ocr）**、source_dept、effective_from、effective_to、parse_status、chunk_count、version | file_hash 唯一；索引 parse_status |
| `kb_chunk` | 切片 | kb_file_id、ordinal、content、token_count、vector_id、meta_json | 索引 (kb_file_id, ordinal) |
| `parse_task` | 解析任务 | kb_file_id、stage、status、error、started_at、finished_at | 索引 status |
| `search_cache` | 外网搜索缓存 | query_hash、source、result_json、expires_at | query_hash 唯一 |
| `api_quota` | 每日配额 | user_id、quota_date、used | 唯一 (user_id, quota_date) |
| `audit_log` | 审计 | actor_id、action、target、ip、trace_id | 索引 (actor_id, created_at) |
| `model_version` | 模型版本 | name、base_model、base_revision、adapter_path、eval_score、status | 索引 status |
| `schema_version` | 迁移版本 | version、applied_at | 主键 version |

## 3. 与 ChromaDB 的关系

向量只在 ChromaDB，MySQL 只存 `vector_id` 与业务元数据。切片正文两边都存：Chroma 的 document 用于返回原文，MySQL 的 content 用于管理与重建。删除时先删向量再删记录，避免"查到但打不开"。

## 4. 待定项（P1-01 决策）

学分计算规则表是否独立（当前计划放代码常量）；`audit_log` 是否按月分区（数据量小，先不分区）。
