# P9 镜像保存与演示前导入

> 2026-11-15。关键前提：平台“备份镜像”**只固化系统盘，不含 `/hy-tmp`**；本项目代码、venv、模型、数据库、Chroma、上传件全部在 `/hy-tmp/campus`。**只导入镜像无法启动完整服务**，必须同时恢复 `/hy-tmp` 数据或继续使用原实例。

## 1. 两种演示保障方式

### 方式 A（推荐）：保留原实例 + 镜像兜底

- 演示前不释放实例，保持 `/hy-tmp` 原样；
- 每天 `bash scripts/backup.sh` 到 OSS；
- 镜像只作为“系统环境坏了”的兜底，不承担数据恢复。

### 方式 B：镜像 + OSS 数据恢复

1. 在控制台创建备份镜像（系统盘）；
2. 把 `/hy-tmp/campus` 的应用数据、DB、Chroma 备份到 OSS；
3. 演示前用镜像创建新实例；
4. 恢复 `/hy-tmp/campus`（appdata + db + chroma；venv 可用 `install.sh` 重建或恢复 venvs 包；模型用 `scripts/fetch_models.sh` 重新下载约 20GB）；
   - **注意**：appdata 内含 `.env`。恢复时先解包 appdata，用 `.env` 里的密码创建 MySQL 用户，再导入 DB；不要先让 `install.sh` 生成新 `.env`，否则密码对不上。`install.sh --skip-db` 只建 venv/模型，不动库。
5. `bash scripts/start.sh`，`/readyz` 四项 ok；
6. 跑 `scripts/seed_demo_chats.py` 重置三角色示例。

> 若平台支持“数据盘快照/整机快照”，以控制台实际能力为准；本手册按“镜像只含系统盘”的已知事实编写。

- [ ] 用户确认实例余额与镜像配额。
