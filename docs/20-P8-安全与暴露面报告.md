## 2. 公网暴露面（P8-06）

从沙箱外部对 `i-2.gpushare.com` 做 TCP 连接测试（非全端口扫描）：

| 端口 | 结果 | 说明 |
|---|---|---|
| 22 | timeout | 未开放 |
| 80 / 443 | timeout | 未开放 |
| 3306 / 8001 / 8002 / 8080 | timeout | 仅内网监听，公网不可达 |
| 31209 | **open** | SSH 平台映射（运维入口） |
| 44368 | **open** | 平台自定义服务 → 内网 8080（HTTP） |

其他检查：

- 公网 `/metrics`：404（仅服务器本机可访问，符合设计）。
- 前端产物 `frontend/dist` 23 个资源文件：**未发现** `ANYSEARCH`、`JWT_SECRET`、`MYSQL_PASSWORD`、`sk-*`、测试口令。
- 错误页：无堆栈；未知路由 404/3001、JSON 损坏 422/4001、方法不匹配 405/1001。
- CORS：仅配置允许的前端源；恶意 Origin 不返回 ACAO。
- 默认口令：保留（D-22），已在安全报告列为残余风险。

**口径修正**：计划旧文“公网仅 22/443 开放”与实测不符；实际公网入口是 **31209（SSH）+ 44368（HTTP）**，22/443 未开放。已记入 D-23，P8-06 验收按实测口径。

## 3. 控制台确认

2026-11-15 用户提供控制台截图：**“自定义服务”入口打开的就是 `http://i-2.gpushare.com:44368/#/chat` 应用**，与外部实测一致。截图未包含安全组端口列表，端口暴露结论以外部 TCP 实测为准（22/80/443/3306/8001/8002/8080 均不可达，仅 31209 与 44368 可达）。

另观察到：平台“实例监控”显示 GPU 0/24GB、0%，与容器内 `nvidia-smi` 的 21.6GiB 不一致。**显存/GPU 监控以容器内 `nvidia-smi` 为准**，P9-06 巡检不依赖平台监控页。

## 4. 结论

高危 0；中危为“双扩展名上传可入库但解析失败（P2，无执行）”和“保留弱口令（D-22，有锁定补偿）”；其余检查通过。暴露面清单按实测 31209 + 44368，8080/3306/8001/8002 仅内网。
