## 4. 已定型的关键设计（别推翻）

1. **级联检索**：永远先跑静态 RAG；top1 ≥0.80 且没要"最新"就只用知识库，否则补 AnySearch；合并后统一重排，阈值 0.20、最多留 3 条。
2. **查询改写用官方术语**（不做同义词表）：路由一次调用同时产出意图 + 关键词，提示词要求口语换公文说法；知识库文件名前 30 个作为"参考用词"注入（60s TTL）。关键词检索最高分 <0.50 视为改偏，自动用原句再检一次并合并。
3. **联网证据门禁**：正文 <80 字或没有完整句子的网页不进证据集（导航页/目录页会引出"正确的废话"）。
4. **回答落地校验**（`backend/app/services/grounding.py`）：书名号标题、带单位数字、"包括/如/例如"后的顿号列举必须在证据原文里找得到（页眉打断允许二元组 80% 匹配）；越界编号算违规。违规先就地重写一次（只改分句），仍违规则删句，删空降级拒答。结果走 SSE `replace` 整段替换，落库只存修正版。
5. **SSE**：`meta → delta* → [replace] → citation → done`，2.5s 一次 `: ping`（平台代理空闲 4 秒断流）。断线用 `asyncio.shield` 保住落库。
6. **配额三层**：24h 查询缓存 → 每用户 60/日 → 全局 1800/日；个人超限不消耗全局。
7. **轨迹落库**：`agent_trace` 表，一条消息一行（1–3KB，无算力开销），`GET /conversations/{id}/trace` 可复盘；删会话级联删。

## 8. 已知坑（踩过，别再踩）

- 登录失败与令牌过期都是 `401 + code 2001`，前端必须特判 `/auth/login`。
- 检索效果差先怀疑**用词不一致**（同一片段口语 0.037 / 规范化关键词 0.990），不要先怀疑向量化。
- **不要拿原句对 KB 结果二次重排**：会二次降分筛掉正确证据；只给联网结果补分。
- 往 `ref([])` 里 push 普通对象再逐 token 改它是**不会触发渲染**的（表现为"整段一次性蹦出"），必须 `reactive()`。
- 实例重启后 MySQL 不会自启，`start.sh backend` 已内置探测并拉起。
- MySQL 需 `cryptography`；`mysqldump` 要 `-h127.0.0.1 --no-tablespaces`，否则静默导出 20 字节空文件。
- `oss` CLI 没有 bucket 名（`oss://` 就是根），不接受 `.tgz`/`.txt`，`oss rm` 要 `-f`。
- 前端构建必须在虚机本地盘（`/tmp/fe`）做，Windows 共享目录装 npm 极慢；Vite 8 的 `manualChunks` 只接受函数；构建产物部署前先 `rm -rf dist`，否则服务器上会残留旧 hash 文件。
- `pkill -f "npm install"` 会杀掉自己的 SSH 会话，用 `np[m]` 写法。
- PDF 页眉会把表格名切成两半（"海南热带海洋 -167- 海南热带海洋学院 …申请表"），落地校验用二元组容忍。
